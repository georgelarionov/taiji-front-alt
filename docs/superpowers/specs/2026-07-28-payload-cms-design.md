# Payload CMS для сайта Общества — дизайн

Дата: 2026-07-28
Статус: реализовано (см. «Итог» в конце)

## Цель

Перевести контент сайта на редактирование через Payload CMS и поднять всё на Railway.
Ближайшая задача — демонстрация: админка с реальными полями и реальными данными
(не заглушками), сайт собирается из CMS.

## Принятые решения

| Развилка | Решение | Почему |
|---|---|---|
| Как сайт получает контент | SSG + пересборка по вебхуку | Сохраняем текущую статику на Caddy, скорость и всю анимационную обвязку; изменения выезжают за 1–3 мин |
| Объём | Данные + тексты страниц (глобалы) | Всё, что меняется в жизни сайта; лонгриды `/taijiquan/*` — вне объёма |
| БД | Postgres (сервис Railway) | Нативен для Railway, не зависит от тома, переживает редеплой |
| Медиафайлы | Railway Volume на сервисе `cms` | Проще и дешевле S3-бакета; публичные URL отдаёт сам Payload |
| Railway | Тот же проект `unique-transformation` | Рядом с боевым `web`, общая сеть и переменные |
| Тело статьи | Конструктор блоков Payload (не Lexical) | 1:1 ложится на существующий `ArticleBody.astro` — фронтенд не переписываем |

## Архитектура

### Монорепо

```
apps/web      Astro 6, SSG — как сейчас
apps/cms      Next.js + Payload 3 (Payload живёт внутри Next-приложения)
packages/types  типы, сгенерированные Payload (payload-types.ts), общие для web и cms
```

### Railway (проект `unique-transformation`)

| Сервис | Что | Ключевое |
|---|---|---|
| `web` | Astro SSG → Caddy | `RAILPACK_SPA_OUTPUT_DIR=apps/web/dist`, Start Command пустой (не трогаем), добавляется `PUBLIC_CMS_URL` |
| `cms` | Next.js + Payload | Build `pnpm --filter cms build`, Start `pnpm --filter cms start`, свой домен, том `/data/media` |
| `Postgres` | БД | `DATABASE_URL` прокидывается в `cms` референс-переменной |

Переменные `cms`: `DATABASE_URL`, `PAYLOAD_SECRET`, `PAYLOAD_PUBLIC_SERVER_URL`,
`MEDIA_DIR=/data/media`, `RAILWAY_API_TOKEN` + `WEB_SERVICE_ID` + `WEB_ENVIRONMENT_ID`
(для кнопки пересборки).

### Поток данных

```
редактор → админка Payload → Postgres + том с медиа
                                   │
                      сборка apps/web тянет REST API Payload
                                   │
                     мапперы lib/cms/*.ts → существующие типы
                                   │
                        компоненты Astro (не меняются)
```

Публикация: `afterChange` в коллекциях и кнопка «Опубликовать на сайте» в админке
дёргают Railway API на редеплой сервиса `web`.

## Модель контента

### Коллекции

**`users`** — редакторы (встроенная аутентификация Payload).

**`media`** — загрузки. Поля: файл, `alt`, `caption`. Размеры генерируются на загрузке:
`card` 664, `wide` 996, `full` 1328 (совпадают с `widths` в текущих `<Image>`), плюс превью
для админки.

**`documents`** — PDF для `/society`. Поля: файл, название, категория. Размер файла берётся
из метаданных Payload (сейчас читается `fs.statSync` на сборке).

**`news`** — новости. Поля:
- `slug`, `date` (дата), `title`, `shortTitle`, `excerpt`, `readingTime`
- `image` → `media`, `imageAlt`
- `isConference` — галка «материал первой конференции» (питает хаб на `/research`)
- `author` — группа `name` / `role`, по умолчанию Общество
- `body` — конструктор блоков: `Абзац` (текст + галка «лид»), `Подзаголовок`, `Список`,
  `Изображение` (→ `media` + подпись), `Цитата`, `Видео` (RuTube-эмбед)
- черновики и версии включены (`versions.drafts`)

**`videos`** — медиа-архив. Поля: `slug` (для якоря `#video-<id>`), `date`, `title`,
`desc` (массив абзацев), `embeds` (массив: URL RuTube + необязательная подпись части).

**`research`** — материалы раздела «Исследования». Поля: `kind` (Источник / Публикация),
`year`, `title`, `desc`, `label` (видимый домен), `url`.

**`events`** — анонсы. Поля: `date`, `title`, `desc`, `place`, `url`, `status`
(предстоящее / прошедшее). Сейчас на сайте заглушка — CMS её оживляет.

**`team`** — правление Общества. Поля: `role`, `name`, портрет → `media`,
`description` (абзацы), `history` (пункты биографии; пункт = абзац либо абзац со вложенным
списком), порядок сортировки.

**`persons`** — персоналии тайцзицюань. Поля: `name`, `cjk` (иероглифы), `line`, `card`
(краткий текст), `meta` (пары ярлык/значение), `bio` (абзацы), `sources` → связь с
`taiji-sources`.

**`taiji-sources`** — общий пронумерованный список источников: `n`, `title`, `desc`, `url`,
`label`.

**`partners`** — партнёры: название, логотип → `media`, ссылка.

### Глобалы

- **`site-settings`** — телефон, e-mail, строка академической поддержки, адрес, часы работы,
  соцсети, `src` карты Яндекса
- **`home`** — две карточки первого экрана (заголовок, описание, изображение, ссылка)
- **`about-block`** — четыре карточки «О тайцзицюань» (заголовок, текст, коллаж)
- **`society-page`** — миссия (заголовок + абзацы) и ценности (для слайдера)
- **`contacts-page`** — тексты страницы контактов
- **`navigation`** — меню и футер (`navCols`, `bigLinks`, `topNav` из `config/nav.ts`)

Интерфейс админки на русском (встроенная локаль Payload), все ярлыки полей — русские.

## Слой доступа на стороне сайта

`apps/web/src/lib/cms/` — по модулю на сущность. Каждый экспортирует функции, возвращающие
**те же типы, что сейчас в `src/data`**: `NewsArticle`, `Block`, `MediaVideo`,
`ResearchItem`, `TeamBio`, `TaijiPerson`. Компоненты и страницы не переписываются — меняется
только источник данных.

Изображения: Payload отдаёт URL и `width`/`height`; в Astro они идут через `<Image>` с
`image.remotePatterns`, то есть оптимизируются на сборке так же, как сейчас локальные
импорты. `inferSize` не нужен — размеры приходят из API.

Если CMS недоступна во время сборки — сборка падает с внятным сообщением. Молча отдавать
пустой сайт нельзя.

## Миграция существующего контента

`apps/cms/scripts/migrate-from-code.ts`:

1. Собирает `apps/web/src/data/**` через esbuild с плагином, который импорты картинок
   (`.jpg/.png/.webp/.svg`) подменяет на абсолютные пути к файлам — иначе модули не
   исполняются вне Astro.
2. Через Local API заливает файлы в `media` и создаёт документы коллекций.
3. Идемпотентно по `slug` / `id`: повторный запуск обновляет, а не дублирует.

Переезжает: 23 новости с фотографиями и блоками, видео медиа-архива, источники и публикации,
шесть биографий правления, персоналии с источниками. Тексты страниц заполняются в глобалы.

Старые `src/data/*.ts` удаляются после переключения страниц на CMS (этап 2), не раньше.

## Этапы

**Этап 1 — CMS живая с реальными данными.** Каркас `apps/cms`, схема коллекций и глобалов,
русская админка, Postgres и том, деплой на Railway, миграция контента. Результат: админку
можно показывать.

**Этап 2 — сайт от CMS.** Слой `lib/cms`, переключение страниц, `image.remotePatterns`,
кнопка пересборки и `afterChange`-хук, зелёный прод-билд, обновление `CLAUDE.md` и
`docs/conventions.md`.

## Риски

- **Payload 3.86 против Next 16.** Официально поддержан Next 15. Ставим через
  `create-payload-app`, он пинит рабочую связку; при конфликте остаёмся на Next 15.
- **Вес медиа.** Сейчас 58 МБ фотографий новостей. Том на 1 ГБ покрывает с запасом, но каждая
  сборка сайта скачивает картинки заново — ожидаемо +1–2 мин к билду.
- **Railway MCP отдаёт `Unauthorized`.** Работаем через CLI (`railway`, залогинен), проект
  линкуем неинтерактивно по id.
- **Стоимость.** Плюс два сервиса и том в проекте `unique-transformation`.

## Вне объёма

- Лонгриды `/taijiquan/{history,theory,practice}` — остаются в коде: редкие правки, самая
  сложная вёрстка на сайте (сноски, врезки, таймлайн, глоссарий).
- Формы (заявка на вступление, обратная связь) остаются моками — приём заявок в CMS это
  отдельная задача.
- Фотогалереи медиа-архива — на сайте заглушка, данных нет.
- Локализация контента на другие языки.

## Итог (2026-07-28)

Сделано по обоим этапам:

- `apps/cms` — Payload 3.86 + Next 16.2 + Postgres, админка на русском, домен
  `https://cms-production-4b9a.up.railway.app/admin`, том `/data` под медиа.
- Мигрировано: 23 новости (с блоками и фото), 3 видео, 5 материалов исследований,
  6 биографий правления, 6 персоналий + 10 источников, 2 PDF, 48 медиафайлов, шесть
  глобалов с текстами страниц.
- Сайт читает CMS: слой `apps/web/src/lib/cms/*`, обёртка `CmsPicture.astro`,
  `image.remotePatterns` в `astro.config.mjs`. Проверено полной сборкой против
  прод-CMS: 40 страниц, `pnpm check` — 0 ошибок.
- Кнопка «Опубликовать на сайте» в админке (`POST /api/rebuild-site`).

Отклонения от плана:

- Поле массива соцсетей названо `network`, а не `id` (в Postgres `id` — служебный ключ
  строки массива).
- В коллекцию «Документы» добавлено поле «Подпись» — строка под названием была в вёрстке.
- Портреты персоналий тайцзицюань жили в компоненте, а не в датасете; заведены в CMS.
- `apps/web/src/config/{nav,socials}.ts` удалены — их заменил глобал «Навигация».
- `apps/web/src/data/**` оставлены как исходник для сидинга; сайтом не читаются.

Закрыто после первичного отчёта:

- Токен положен в переменные сервиса `cms`. Он оказался **проектным**, а такие Railway
  принимает заголовком `Project-Access-Token`, а не `Authorization: Bearer` — 
  `lib/railway.ts` теперь пробует оба. Мутация `serviceInstanceRedeploy` проверена
  вживую: вернула `true`, сборка прошла.
- Всё закоммичено и запушено в `main` (efb2230); боевой сайт пересобран и отдаёт
  контент из CMS — проверено на главной, статье, персоналиях и документах.
